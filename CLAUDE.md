# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

MCPokédex — an agentic chat (Gemini-style) that answers Pokémon questions as "Dexter". A FastAPI backend runs a [strands-harness](https://github.com/strands-agents/harness-sdk) agent connected to the [`mcp-pokemon-server`](https://github.com/ShimaCoding/mcp-pokemon-server) MCP server. Tools that declare an MCP Apps widget (`_meta.ui.resourceUri`) render inline in the chat: the frontend acts as the MCP Apps **host**.

LLM: Groq only, through LiteLLM. Anonymous requests use `gpt-oss-20b`; requests with a valid `X-API-Key` use `gpt-oss-120b` with fallback to `gpt-oss-20b` (strands `ModelRouter`).

## Running the App

```bash
uv sync                                         # deps pinned in uv.lock
uv run uvicorn backend.main:app --reload        # backend on :8000
cd frontend && npm run dev                      # Vite on :5173, proxies /api, /config, /health
uv run pytest                                   # backend tests
docker-compose up --build                       # production-like
```

`.env` needs `GROQ_API_KEY`. For a local MCP server set `MCP_SERVER_URL=http://localhost:8001/mcp`. Dependencies are locked: update with `uv lock --upgrade-package X`, never with open ranges.

## Architecture

- **`backend/providers.py`** — Groq model lists and `build_model()`, which returns a `ModelRouter` of `TracedLiteLLMModel`s. `TracedLiteLLMModel` reports each attempt (`llm_call`, `model_attempt`) to a per-request trace sink. Nothing in litellm is patched.
- **`backend/agent.py`** — `create_agent()` builds the harness with everything unsafe for a public site disabled (`builtin_tools=[]`, `builtin_plugins=[]`, `memory=False`, `background_tasks=False`). The agent exposes exactly `EXPECTED_TOOLS` (MCP tools + `retrieve_context`); `backend/tests/test_agent.py` enforces it. The Dexter narration protocol is inline in `SYSTEM_PROMPT` (`skills=False`, no harness skill), and `create_agent` re-applies `SYSTEM_PROMPT` after the session restore because snapshots persist the system prompt. `NormalizePokemonNames` turns Pokémon-name tool arguments into PokeAPI slugs ("Mr. Mime" → `mr-mime`, `giratina` → `giratina-altered`); the MCP server only lowercases. Never enable long-term memory: it is shared across all visitors.
- **`backend/sessions.py`** — `conversation_id` validation (`^[a-z0-9-]{8,64}$`, generated by the browser), a per-conversation `asyncio.Lock`, and TTL cleanup of `SESSIONS_DIR` (harness snapshots under `session/<id>` and `context/<id>`).
- **`backend/telemetry.py`** — Datadog LLM Observability via the ddtrace SDK in agentless mode (no Datadog Agent, APM tracer off), enabled by `DD_API_KEY`. Each request is an `agent` span (session = `conversation_id`, opened in `_sse_generator`) with an `llm` span per model call (`TracedLiteLLMModel.stream`: messages, output, tokens incl. cached) and a `tool` span per tool call (`_ToolTrace`). Without the key every helper is a no-op. Strands' OTel export is not used: its OTLP spans reached Datadog APM but never LLM Observability.
- **`backend/mcp_gateway.py`** — short-lived MCP connections for non-agent endpoints: widget HTML (`read_ui_resource`) and widget tool calls (`call_ui_tool`), both restricted to UI-bound tools and cached for 5 min.
- **`frontend/`** — React + Vite chat (builds into `backend/static`). `hooks/useAgentStream.ts` streams a reply into the chat store as ordered text/widget parts plus traces; `components/Widget/WidgetFrame.tsx` is the MCP Apps host (sandboxed `srcdoc` iframe with CSP from `_meta.ui.csp`, `AppBridge` over postMessage, lazy-loaded); `components/Thinking/ThinkingPanel.tsx` is the "ver cómo lo pensó" trace panel. `conversation_id` and recent messages persist in localStorage; "Nueva" starts a new conversation.
- **`backend/main.py`** — FastAPI app. `POST /api/agent/run` streams SSE; `GET /api/ui-resource?uri=` and `POST /api/mcp/call-tool` back the widget bridge. Static frontend mounted at `/`.

## SSE contract

Each event is `data: <json>\n\n`; `type` is one of `start`, `agent_init`, `llm_call`, `model_attempt`, `tool_call`, `tool_result`, `ui_resource`, `text`, `done`, `error` (full shapes in the `_sse_generator` docstring). `tool_call`/`tool_result`/`ui_resource` share `tool_id` and `index`. `ui_resource` carries `resource_uri`, `tool_input` and `tool_result` (MCP `CallToolResult` shape with `structuredContent`) — everything the frontend needs to mount the widget. New event types must also be added to `EVENTS_CATALOG` in `backend/wiki_content.py` (a test checks it).

## Key Design Decisions

- **Agent per request**: the harness agent (and its MCP connection) is built per request in a worker thread and cleaned up afterwards; conversation memory lives in the session snapshot, not in the process.
- **Widgets never talk to MCP directly**: the iframe is sandboxed (`allow-scripts` only) and the browser has no MCP client, so widget requests go through the backend endpoints above.
